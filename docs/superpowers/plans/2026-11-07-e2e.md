# End-to-end tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (the owner chose native execution for every plan). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Drive the real Electron app end to end with Playwright (Linux and Windows), including the Windows installer, with a real-save variant that runs only locally.

**Architecture:** An *e2e build* (`dist-e2e/`) holds the same main, preload and UI as the product, with only `importer.cjs` replaced by a scripted importer that writes an invented snapshot. Playwright's `_electron.launch` starts it with a fresh `--user-data-dir` per scenario and stubs the native open dialog from outside. A separate Windows-only spec runs the real installer silently and launches the installed app on seeded data. A local-only spec uses the real build and `saves/*.fm`.

**Tech Stack:** `@playwright/test` (devDependency; no browser download), esbuild (already present), Vitest for the unit tests of the fake importer.

**Spec:** `docs/superpowers/specs/2026-11-07-e2e-design.md`

## Global Constraints

- No test-only environment variables or flags in `src/` (spec, Non-goals). Product code changes only if a scenario proves a missing accessible handle, and then with a component test.
- Playwright is a devDependency; never listed in `electron-builder.yml` `files` (it already only packs `dist/**`, `dist-electron/**`, `package.json`).
- Fixtures contain invented players only; no save content, no real people. Public repo.
- Vitest keeps `include: tests/**/*.test.{ts,tsx}`; e2e files are named `*.spec.ts` so Vitest never picks them up, and Playwright's `testDir` is `tests/e2e`.
- Real-save spec skips itself when no save exists (`findSampleSave()` in `tests/helpers/sample.ts`).
- Pointer drags that prove unstable on CI are `test.fixme` with the reason in the test and in `docs/09-distribution.md`; never weakened until they pass.
- Each scenario uses its own temp data folder (`--user-data-dir`); the real `%APPDATA%` is touched only by the installer spec, which runs on the CI runner.
- Commit messages end with the attribution lines from the session reminder.

## Review Focus

- A scenario that passes because the assertion is vacuous (e.g. looks for text that is also present before the action). Each "after" assertion must be shown false before the action (RED) at least once.
- Close-then-reopen racing the debounce: the edit must be asserted from the second launch only, after the first process has exited.
- Cancel mid-import must leave `snapshot.json` byte-identical (assert on the file, not only the UI).
- The scripted importer drifting from the snapshot contract: its output must pass `isSnapshot` in a Vitest test.
- Orphan processes: every launched app is closed in `afterEach`, and the installer spec uninstalls even when assertions fail.

### Task 2: Invented squads and the scripted importer

**Files:**
- Create: `tests/e2e/support/squads.ts`, `tests/e2e/support/e2e-importer.ts`, `scripts/build-e2e.mjs`, `tests/electron/e2e-importer.test.ts`
- Modify: `package.json` (`build:e2e`)

**Interfaces:**
- Produces in `squads.ts`: `export function squadA(): Snapshot` (18 invented first-team players with uids 9001..9018, names like "Jugador Uno", natural positions covering GK, 4 defenders, 4 midfielders, 3 forwards plus bench) and `export function squadB(): Snapshot` (squadA minus uid 9018, plus a new uid 9101 named "Jugador Nuevo"). Both pass `isSnapshot`.
- Produces `e2e-importer.ts`: a process entry with the same stdout JSON-line protocol as `src/importer/run.ts` (`progress`, `done`, `error`). It reads the file at argv[2] (the "save", a small JSON file `{ "squad": "A" | "B", "hang"?: true }`), emits at least two progress lines, writes the snapshot atomically to argv[3], emits `done`. With `hang: true` it emits one progress line then never finishes (so the test can cancel). Unreadable "save" gives `error` code `NOT_A_SAVE`.
- Produces `build-e2e.mjs`: creates `dist-e2e/` containing `package.json` (`{"name":"fm24-e2e","main":"dist-electron/main.cjs","version":"0.0.0"}`), `dist-electron/{main,preload}.cjs` bundled as in `scripts/build-electron.mjs`, `dist-electron/importer.cjs` bundled from `e2e-importer.ts`, and `dist/` copied from the built UI. `build:e2e` = `build:ui` then this script.

- [ ] **Step 1:** Write `tests/electron/e2e-importer.test.ts` (Vitest): `squadA()` and `squadB()` satisfy `isSnapshot`; B differs from A exactly by uid 9018 removed and 9101 added; running the bundled importer as a child process (via the fake `node` + built file, using `importRunner` from `src/electron/importRunner.ts`) on a `{"squad":"A"}` file yields `done` and a file that passes `isSnapshot`; `{"hang":true}` never emits `done` within 300 ms. Run: `npx vitest run tests/electron/e2e-importer.test.ts`. Expected: FAIL (modules missing).
- [ ] **Step 2:** Implement `squads.ts` (reuse `snapPlayer`-style construction; do not import from `tests/helpers` if it pulls vitest, copy the small builder) and `e2e-importer.ts`.
- [ ] **Step 3:** Implement `build-e2e.mjs` and `build:e2e`. Run `npm run build:e2e` then the Vitest file. Expected: PASS. Run `npm test` and `npm run typecheck`. Expected: green.
- [ ] **Step 4:** Commit `test(e2e): scripted importer and invented squads for the e2e build`.
